# Pharos (파로스) — 마스터 플랜 및 서비스 아키텍처 (v2.0)

> v1.0(앱·게임 MVP)에서 나아가, **세상 모든 대상(앱·게임·콘텐츠·AI 툴·제품 등)을 평가·선별하는 실제 공개 서비스**로 확장하기 위한 구조 정비 및 보완 계획.

---

## 1. 핵심 방향과 분류 계층 (4단 보편 구조)

기존 MVP의 `비교군 → 앱/게임` 역전 구조와 `전체` 평균 혼합 문제를 폐기하고, 분야가 수십·수백 개로 늘어나도 무너지지 않는 **4단 계층**을 도입한다.

| 단계 | 역할 | 예시 |
| :--- | :--- | :--- |
| **1. 도메인 (Domain)** | 최상위 세계 전환 | 앱 · 게임 · (추후) 콘텐츠 · AI 툴 · 제품 |
| **2. 대분류 (Category)** | 도메인 안의 큰 갈래 | 생산성·지식관리, 유틸리티 / 전략·카드, RPG |
| **3. 비교군 (Arena)** | 실제 대체제 묶음 | 노트·지식관리, 할 일 관리, 덱빌딩 게임 |
| **4. 항목·티어 (Item·Tier)** | 실제 선택 및 판정 단위 | Obsidian(무료/Sync), Balatro(1회 구매) |

- **비교 원칙**: 점수 평균, 순위, 요약 지표는 **오직 같은 비교군 안에서만** 계산한다. 서로 다른 분야(예: 노트 앱 vs 카드 게임)를 한 줄에 섞어 평균 내지 않는다.

## 2. 평가 엔진: 공통 코어 + 도메인 팩

세상 모든 것을 하나의 기준으로 묶지 않고, **공통 코어** 위에 **도메인별 필터·속성 팩**을 얹는다.

- **공통 코어 (모든 도메인 공유)**:
  1. **대중 평가 (`user_rating`)**: 최근 구간 vs 누적 괴리, 표본 신뢰도 보정
  2. **객관·신뢰 지표 (`objective`)**: 가격 투명성, 유지/지속성, 정직성
  3. **AI 검토 (`ai_review`)**: 본질 완성도, 함정 구조, 강점/약점 요약
  4. **근거 등급 (`A/B/C`) & 미확인(`⚪`) 원칙**: 근거 없는 추정 금지
  5. **티어/옵션 단위 판정**: 무료/구독/1회 구매 등 실제 선택지별 분리 판정
- **도메인 팩 (필터·메타데이터 분리)**:
  - **게임 팩**: 확률형 아이템, P2W, 강제 광고, 완결작(`feature_complete`) 방치 면제. 확률형·P2W 는 v0.4.0부터 **강도 3단계**(`impact`: none·optional·core)로 나눠, 무과금으로 충분한 상품(optional)은 배지로만 알리고 `strict_monetization` 토글로 거를 수 있다.
  - **앱 팩**: 구독 필수, 과도한 데이터 수집, 내보내기/락인, 계정 필수
  - **확장 팩(추후)**: 콘텐츠(완결·전개), AI 툴(종량제·환각·데이터 학습 정책) 등
  - 웹 UI의 필터·프리셋 패널도 선택한 도메인에 맞는 항목만 우선 노출한다.

## 3. 실제 서비스를 위해 보충한 6가지 핵심 요소

프로토타입을 넘어 일반 사용자가 실제로 믿고 쓰고 다시 찾아오는 서비스가 되기 위해 아래 6가지를 기본 구성에 포함한다.

### ① 신뢰·반론(이의제기) 루프 및 신선도 경고
- **평가 시점·신선도 경고**: `assessed_at` 기준 경과 기간(예: 180일 초과 시 `"재검토 필요"` 배지)을 노출해 낡은 판정이 최신 사실처럼 보이지 않게 한다.
- **이의제기·패치 제보 통로**: 앱/게임은 업데이트 한 번으로 광고·과금 정책이 바뀐다. 개발사나 사용자가 근거 링크와 함께 정정을 요청할 수 있는 **GitHub Issue 템플릿**을 연결한다(서버비 0원).
- **독립성 명시**: 어필리에이트·유료 광고 배제 원칙을 사이트 소개에 명시한다.

### ② 목적 중심 진입 & 대체제 연결 (탐색 피로 해소)
- **홈/랜딩 요약 뷰**: 첫 방문자가 5초 안에 서비스 가치를 알 수 있도록 ① 주요 비교군 바로가기, ② `"별점은 높은데 거름 판정"` 리포트, ③ 통합 검색(`"에버노트 대신 뭐 쓰지?"`)을 전면에 둔다.
- **대체제 연결**: 거름/조건부 판정 항목(예: Evernote)의 상세 화면 하단에 **같은 비교군 내 상위 추천 대체제(Joplin·Obsidian)**로 바로 이동하는 링크를 붙인다.

### ③ URL 딥링크 & 공유 완성도
- **URL 상태 동기화**: 선택한 도메인·비교군·상세 항목·가중치 프리셋을 쿼리 파라미터(`?domain=app&arena=pkm-notes&item=obsidian`)에 반영해 링크 공유 시 같은 화면이 열리게 한다.
- **공유용 요약 복사 & OG 메타**: 항목/비교군 판정을 커뮤니티 글에 붙이기 좋은 텍스트/카드 포맷으로 복사하고, 주요 비교군 정적 진입 페이지에 OG 메타태그를 지원한다.

### ④ 첫 화면 온보딩 & 모바일 UX 경량화
- **주인공은 콘텐츠**: 현재 왼쪽에 크게 고정된 가중치 슬라이더·필터 9개는 처음 온 사용자에게 조작 부담을 준다. 기본 화면은 `"균형 기본"` 프리셋으로 깔끔히 보여주고, 세부 조절은 **`내 기준 미세조정` 토글/드로어** 안으로 정리한다.
- **용어 인라인 도움말**: `근거 등급 A/B/C`, `하드 필터`, `엄격 모드` 등 낯선 개념에 짧은 툴팁·설명을 붙인다.

### ⑤ 기준·방법론 안내 페이지 (투명성)
- **"파로스가 점수를 매기는 법"** 전용 모달 또는 페이지를 두어 4축 구조, A/B/C 근거 등급 기준, 왜 단일 별점을 쓰지 않는지 투명하게 공개한다.

### ⑥ 사실(Fact)과 의견(Opinion)의 엄격한 분리 & 법적 안전선
- 공개 서비스 리스크(명예훼손·저작권) 방지를 위해 스토어 표기·가격·업데이트 날짜 등 **객관적 사실은 출처 URL + 근거 등급 A**로 고정하고, AI/편집 평가는 **기준표에 따른 검토 의견**으로 명확히 구분한다. 스토어 이미지 무단 복제 없이 텍스트·수치·공식 링크 중심으로 구성한다.

## 4. 시스템 아키텍처 (서버비 0원 우선 전략)

- **데이터 카탈로그 분리**:
  - `data/catalog.json`: 도메인 · 대분류 · 비교군 정의 (기존 `item.schema.json` 내 `x-pharos.client.arenas` 하드코딩 분리)
  - `data/{domain}/{arena}.json` (또는 도메인별 분할 파일): 항목 데이터 분할 저장 → 수백 건으로 늘어나도 필요한 비교군만 지연 로딩(Lazy Load) 가능
  - `scripts/build_web_data.py` (기존 `sync_web_data.py` 확장): 분할 데이터를 검증(`validate.py`)하고 인덱스·웹 사본을 생성
- **정적 웹 호스팅**: 빌드 도구 없는 ES Module 정적 웹을 `web/`에 두고 GitHub Pages(`AIRA1346/pharos`)로 0원 배포.
