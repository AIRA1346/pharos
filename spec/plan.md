# Pharos (파로스) — 서비스 및 시스템 구조 계획 (v1.0)

## 1. 서비스 형태 (무엇을 어떻게 보여주는가)
- **한 줄 정의**: 내 기준(노 광고·노 P2W·최근 평점 유지 등)으로 AI 양산형과 함정 앱을 걸러내고 진짜 쓸 만한 것만 남겨주는 **다층 선별 큐레이션**.
- **핵심 사용자 흐름**:
  1. **내 기준 설정**: 절대 거름 조건(Hard Filter: 확률형 과금 제외, 강제 전면 광고 제외 등)과 축별 가중치(사용자 평가 / 객관 지표 / AI 검토)를 조절하거나 프리셋 선택.
  2. **신호등 목록 탐색**: `[🟢 추천 / 🟡 조건부 / 🔴 거름]` 상태와 축별 신호, 한 줄 판정으로 빠르게 스캔.
  3. **상세 교차 검증 뷰**: 누적 vs 최근 리뷰 괴리, 티어별(무료/유료) 판정, 과금·미끼 광고 팩트, 근거 출처 등급(A/B/C) 확인.
  4. **공유**: 특정 앱·게임의 파로스 판정 카드나 내 선별 리스트를 이미지/링크로 공유.

## 2. 시스템 아키텍처 (서버비 0원 우선 전략)
초기부터 상시 백엔드 서버와 DB를 두면 유지비·크롤링 관리 부담이 커지므로 **정적 웹 + 배치 파이프라인** 구조를 1순위로 채택한다.

- **데이터 파이프라인 (오프라인 / 배치)**:
  1. `Collector`: Steam, Google Play, App Store, 커뮤니티(Reddit 등) 메타데이터·리뷰 수집
  2. `Fact Extractor`: 가격, 티어, 확률형 아이템 표기, 업데이트 주기, 광고 표기 등 하드 팩트 정제
  3. `AI Reviewer`: `criteria.md` v0.3.1 기준으로 JSON 평가 데이터 생성 (근거 등급 A/B/C 태깅, `maintenance_status`로 완결작·방치 구분)
- **웹 서비스 (프론트엔드)**:
  - 수집·생성된 `items.json`을 정적 웹(Next.js/Vite 정적 빌드)에 묶어 **Cloudflare Pages / Vercel / GitHub Pages**에 배포.
  - 사용자의 **가중치 슬라이더·하드 필터 계산은 브라우저(클라이언트)에서 즉시 처리** → 서버 비용 0원, 빠른 응답 속도.
- **추후 확장 (옵션)**: 유저가 목록에 없는 앱을 직접 분석 요청하는 기능은 수요 검증 후 경량 API/큐를 붙이는 2단계로 분리.

## 3. 단계별 실행 로드맵
- **Phase 1 · 기준표 v0.2 확정 & 수집·평가 파이프라인**: 파일럿에서 찾은 4가지 보완점 반영 후, 실제 앱·게임 20~30종 자동 수집 및 JSON 생성 테스트.
- **Phase 2 · 파로스 웹 MVP 구축 (로컬 → 정적 배포)**: 신호등 카드 UI + 가중치 슬라이더 + 티어별 필터가 작동하는 웹 프로토타입 제작.
- **Phase 2.5 · 비교군(Arena) 구조 & 실전 데이터 확장 (스키마 v0.3)**: 장르·용도별 비교군 태그(`arenas`)를 도입해 같은 자리를 두고 겨루는 대체제끼리 비교한다. 노트·지식관리 5종, 덱빌딩 게임 4종, 모바일 수집형 RPG 1종(10건)으로 데이터를 넓히고 웹에 비교군 탭·요약 재계산을 붙였다.
- **Phase 2.6 · '완결작 vs 방치' 구분 & 정적 배포 준비 (스키마 v0.3.1)**: `maintenance_status`(active·feature_complete·stale_unknown·abandoned)를 도입해 완결 선언된 패키지 게임은 `stale_over_12m` 필터에서 면제한다(Inscryption이 80.15점 → 🟢 추천). 웹은 `web/` 폴더 하나로 GitHub Pages 등에 올릴 수 있게 `web/data`·`web/schema` 사본과 `scripts/sync_web_data.py`를 두고, `validate.py`가 원본과의 일치를 검사한다.
- **Phase 3 · 반응 검증 & 카테고리 확장**: "별점 4.6★인데 거름인 이유" 같은 파로스 리포트를 커뮤니티에 공유해 반응 확인 후, 웹툰·애니·AI 툴 등으로 확장.
